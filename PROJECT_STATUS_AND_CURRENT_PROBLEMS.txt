1. PROJECT OVERVIEW & CORE OBJECTIVES
----------------------------------------------------------------------------------------------------
This project is an end-to-end intelligent traffic surveillance and urban analytics platform developed
for Smart India Hackathon (SIH) under Problem Statement ID 26127 (Bharat Electronics Limited - BEL).

The core objectives are:
  1. Multi-Camera Video Ingestion: Ingest live feeds from IP cameras, RTSP streams, and smartphones
     acting as mobile edge cameras via low-latency WebRTC and Socket.io signaling.
  2. Vehicle & License Plate Detection: Vehicle-first gating (cars, motorcycles, buses, trucks) followed
     by high-precision license plate localization using custom-trained YOLOv8 models.
  3. Indian Registration Standard OCR: Extract license plate characters conforming to Indian Ministry of
     Road Transport and Highways (MoRTH Rule 50) standards (standard rectangular plates, two-row square
     plates, and All-India Bharat Series 'BH' plates).
  4. Perspective & Skew Rectification: Rectify angled/skewed plates using 4-point homography warping
     before OCR to ensure character readability at 30–60 degree camera viewing angles.
  5. Multi-Frame Temporal Validation & Voting: Eliminate single-frame noise, road signs, and billboards
     using confidence-weighted positional character voting across temporal sliding windows.
  6. False-Positive Protection: Enforce a strict 6-stage evidence chain guaranteeing zero false positives
     on non-vehicle scenes, road textures, and billboards.
  7. Multi-Camera Trajectory Tracking & GIS: Chronologically stitch vehicle movements across
     geographically distributed cameras on an interactive Leaflet GIS map with travel time estimation.
  8. Watchlist & Stolen Vehicle Hotlist Alerting: Match recognized plates against law enforcement
     watchlists (stolen, expired registration, wanted) with real-time audio-visual dashboard alerts.
  9. Urban Traffic Analytics: Compute vehicle density, congestion metrics, peak flow periods, and
     camera-to-camera movement patterns based exclusively on ground-truth verified detections.


2. CURRENT SYSTEM ARCHITECTURE & COMPONENTS
----------------------------------------------------------------------------------------------------
The platform operates as a distributed hybrid architecture with fine-grained modularity:

A. CORE BACKEND SERVICE (Node.js / Express / Socket.io / WebRTC Signaling)
   - File: `server.js` (Port 3000, HTTPS with auto-generated self-signed SSL/TLS certificates).
   - Functions:
     * Full-duplex WebSocket / Socket.io server for telemetry, detection alerts, and dashboard sync.
     * WebRTC signaling server (SDP offer/answer, ICE candidate exchange) allowing smartphones to stream
       HD camera feeds directly to the dashboard over local Wi-Fi or LAN.
     * Phase 6 Multi-Camera Concurrency Queue Manager (`MultiCameraQueueManager`):
       - Bounded concurrency with worker semaphore (`maxConcurrency: 2` on CPU).
       - Bounded latest-frame queue per camera (depth = 1): drops stale backlogged frames when newer
         keyframes arrive. Newer frames are strictly prioritized for real-time surveillance.
       - Real-time queue metrics: frames received, processed, dropped, queue wait time, inference latency.
     * REST APIs:
       - Watchlist CRUD operations (`/api/watchlist`).
       - Chronological vehicle trajectory history & GIS segments (`/api/detections/trajectory/:plate`).
       - Urban traffic analytics aggregations (`/api/detections/analytics`).
       - Camera topology configuration (`/api/cameras/config`).
       - Reverse proxy & queue endpoints (`/api/anpr/detect`, `/api/anpr/queue/stats`, `/api/anpr/config`).
     * JSON Persistence: Disk backups for detections (`data/detections.json`), watchlist (`data/watchlist.json`),
       and alerts (`data/alerts.json`) with periodic autosave and clean shutdown handlers.

B. ANPR INFERENCE MICROSERVICE (Python 3.14 / FastAPI / PyTorch / ONNX Runtime / YOLOv8 / Tesseract / EasyOCR)
   - File: `scripts/anpr_server.py` (Port 5001, HTTP).
   - Multi-stage pipeline:
     * Stage 1 - Vehicle-First Detection: COCO YOLOv8 model detects vehicles (`car`, `motorcycle`,
       `bus`, `truck`) with confidence >= 0.22. Crops vehicle ROI with 5% spatial margin.
       Includes adaptive ROI expansion for two-wheelers/motorcycles where plates sit low on rear mudguards.
     * Stage 2 - License Plate Localization: Trained custom YOLOv8 model (`models/indian_plate_best.pt` /
       `models/indian_plate_best.onnx`) detects plate candidate bounding boxes inside vehicle ROIs
       with confidence >= 0.40. Full-frame fallback disabled by default for strict false-positive gating.
     * Stage 3 - Geometric & Spatial Filtering: Validates plate aspect ratio (1.1 to 6.2 to accommodate
       both MoRTH Rule 50 square plates and standard rectangular plates), minimum dimensions (20x8 px),
       maximum area ratio (<35% of vehicle area), and vertical position (rejects vehicle roof reflections).
     * Stage 4 - Perspective Rectification (Phase 1): Computes 4-point homography and warps tilted crops
       into upright rectangular images. Dual-candidate OCR evaluation tests both original and rectified crops,
       selecting the candidate with higher confidence and syntax validity.
     * Stage 5 - Image Enhancement & Screen Robustness (Phase 5):
       - LAB-space CLAHE local contrast enhancement & glare compensation.
       - Edge-preserving bilateral filtering to suppress LCD subpixel moiré patterns.
       - Adaptive unsharp masking to enhance character edges without amplifying high-frequency noise.
       - Dual-Otsu binarization (standard dark-on-light and inverted light-on-dark).
     * Stage 6 - Staged Early-Exit OCR Pipeline (Phase 4):
       - Tier 1: Fast Tesseract v5.4.0 (PSM 7/8) on standardized target height (80px single-row, 130px two-row).
         Exits immediately if a valid MoRTH plate is recognized with confidence >= 0.75.
       - Tier 2: Alternate PSM modes (PSM 6 for two-row plates) and contrast variations.
       - Tier 3: EasyOCR deep-learning fallback with aspect-ratio-aware reading order.
       - Post-OCR Indian Repairs: Inverted two-row reconstruction (`repair_inverted_two_row`), common OCR
         character stroke repairs ('T' -> '1', 'O' -> '0', 'I' -> '1'), and expanded state code repairs.
     * Stage 7 - Multi-Frame Confidence-Weighted Voting (Phase 7):
       - Sliding window duration: 25.0 seconds.
       - Minimum required sightings: 2 frames.
       - Positional character voting weighted by detector confidence, OCR confidence, and syntax score.
       - Outlier suppression prevents isolated random OCR spikes from overriding consistent sightings.
     * Stage 8 - Dual-Backend Acceleration (Phase 3):
       - Runtime configurable backend (`inference_backend`: `"onnx"` or `"pytorch"`).
       - CPU-optimized ONNX Runtime for YOLO vehicle detection (`models/yolov8n.onnx`).
       - Fine-grained 8-stage latency profiling recorded on every frame.
     * Stage 9 - 16-Point Per-Frame Diagnostics & Visual Archival:
       - Every processed frame records all 16 telemetry parameters.
       - Incoming frames saved to `debug_output/frames/` and pre-OCR plate crops to `debug_output/crops/`.

C. OPERATOR DASHBOARD & FRONTEND (Vanilla HTML5 / CSS3 / JavaScript / Leaflet.js)
   - Files: `public/dashboard.html`, `public/camera.html`, `public/mobile.html`, `public/js/anpr-engine.js`, `public/css/style.css`.
   - Features:
     * Multi-camera video monitoring matrix (Cameras 1 to 4) with real-time video playback and stats HUD.
     * Intelligent Keyframe Selection (Phase 2): Client-side Laplacian variance sharpness filter (>60.0)
       and motion detection buffer. Dispatches only the sharpest useful frame (1 fps) to the backend,
       preventing browser and network congestion while maintaining smooth 60fps video display.
     * Canvas Developer HUD: Renders live cyan bounding boxes for vehicles, crimson dashed boxes with
       failure codes for rejected candidates, amber boxes for accumulating candidates, and neon green
       boxes for confirmed plates. Object-fit and aspect-ratio aware coordinate projections ensure perfect
       bounding box alignment regardless of video container scaling.
     * Interactive GIS Leaflet Map: Plots camera nodes, active vehicle trajectories, and animated routes
       with travel time calculations between junctions.
     * Real-time Detection Feed & Watchlist Alert Banner with audio chimes.
     * Diagnostics Inspector Modal: Displays live stream frame, saved pre-OCR crop, pass/fail telemetry list,
       and runtime threshold tuning sliders.
     * Direct Image Scanner Tool: Allows operators to upload or drag-and-drop static vehicle images for
       instant diagnostic inspection.

D. ONE-CLICK STARTUP & AUTOMATED BENCHMARKING
   - Files: `start_system.bat`, `start_system.ps1`, `scripts/benchmark_anpr.py`, `scripts/diagnose_pipeline.py`.
   - Single-action startup: Verifies Python 3.9+, Node.js 18+, checks node dependencies, verifies port
     availability (3000 and 5001), starts the Python ANPR microservice, awaits health check, starts the
     Node.js platform, and prints local and LAN access URLs.

6. CURRENT PROBLEMS & OPERATIONAL CHALLENGES BEING FACED
----------------------------------------------------------------------------------------------------
While the pipeline is robust, stable, and functionally complete for hackathon demonstration, several
operational and algorithmic challenges remain for production-grade city-wide deployment:

PROBLEM 1: OCR EXACT-MATCH REFINEMENT & CHARACTER AMBIGUITY (HIGH PRIORITY)
  - Issue: Although plate detection recall is 97.14% and average character accuracy is ~61-90% on clean
    plates, OCR Exact Match Accuracy on challenging real-world plates is 11.11%.
  - Root Cause:
    * Visually ambiguous character pairs in standard Indian vehicle number fonts:
      '8' vs 'B', '0' vs 'D' or 'O', '1' vs 'I' or 'T', '5' vs 'S', '2' vs 'Z'.
    * In positions 5-6 (the series letters) and positions 7-10 (the 4-digit unique number), a single
      misidentified character causes an exact-match query failure (e.g., `MP04PA0434` read as `TR04PA0434`
      or `KL41L7001` read as `KL41L2001`).
    * High-Security Registration Plates (HSRP) feature a hot-stamped chromium hologram sticker ('IND' and
      Ashoka Chakra) on the left margin. Standard OCR engines often segment the letters 'I-N-D' as part
      of the registration string (e.g. `INDUBZZAX7LL6` instead of `WB42AX7446`), violating syntax rules.
    * Regional language headers (e.g., Devanagari or Kannada text above the English registration) on
      commercial vehicles can confuse horizontal text segmentation.
  - Mitigation Currently in Place:
    * Positional regex normalization (positions 1-2 must be state codes; positions 3-4 must be digits).
    * Stroke repair dictionary ('T' -> '1' in numeric segments, 'O' -> '0' in numeric segments).
    * Trajectory search allows fuzzy matching (`SequenceMatcher >= 0.75`).
  - Next Step:
    * Implement an HSRP blue-strip / hologram crop mask that trims the leftmost 12% of the plate crop
      if an 'IND' vertical badge is detected.
    * Integrate a fine-tuned CTC character recognition model (e.g., CRNN or SVTR) trained specifically
      on Indian vehicle font glyphs to replace generic Tesseract for the alphanumeric payload.

PROBLEM 2: CPU INFERENCE LATENCY CEILING WITHOUT DEDICATED GPU (MEDIUM PRIORITY)
  - Issue: The system currently runs inference on CPU. Per-frame inference latency averages ~2.8 seconds
    (median 2.7s, p95 5.5s).
  - Root Cause:
    * Executing YOLOv8 vehicle detection + YOLOv8 plate detection + CLAHE enhancement + Tesseract OCR
      on CPU is computationally demanding.
    * While `MultiCameraQueueManager` successfully prevents request backlogs by dropping stale frames
      and keyframe selection limits input to 1 fps, processing 4 cameras simultaneously on CPU saturates
      the worker pool (`maxConcurrency: 2`), forcing camera frames to wait in queue.
  - Mitigation Currently in Place:
    * Phase 3 ONNX Runtime dual-backend with INT8/FP32 CPU graph optimizations.
    * Phase 4 Tier 1 early-exit stops OCR immediately upon recognizing a high-confidence valid plate.
    * Phase 2 sharpness filtering skips blurry frames entirely on the client before network transmission.
  - Solution Needed:
    * NVIDIA CUDA / TensorRT GPU acceleration or Intel OpenVINO / DirectML NPU acceleration to bring
      per-frame inference latency below 50ms, enabling real-time 30 FPS multi-stream processing.

PROBLEM 3: MOTORCYCLE FRONT-PLATE ABSENCE & REAR SARI-GUARD OBSTRUCTION (MEDIUM PRIORITY)
  - Issue: Two-wheelers in India present unique surveillance hurdles:
    * Many motorcycles and scooters do not have front number plates, or only possess vertical stickers
      on the front mudguard that standard horizontal detectors miss.
    * Rear plates are often mounted at steep upward angles and are frequently partially obstructed by
      sari guards, pillion footrests, or rear luggage racks.
  - Mitigation Currently in Place:
    * Two-wheeler ROI expansion dynamically broadens the vehicle bounding box downwards to capture
      low-hanging rear mudguard plates.
  - Solution Needed:
    * Train a dedicated two-wheeler multi-view detector that specifically recognizes front mudguard sticker
      plates and tilted rear brackets.

PROBLEM 4: BROWSER HTTPS SELF-SIGNED CERTIFICATES & CLIENT ISOLATION ON VENUE WI-FI (OPERATIONAL)
  - Issue: The platform uses self-signed SSL/TLS certificates (`cert.pem`, `key.pem`) to satisfy browser
    security requirements for WebRTC and camera access (`getUserMedia`).
  - Impact:
    * Opening `https://<LAN_IP>:3000/camera.html` on mobile Chrome or Safari triggers a "Connection Not Private"
      warning requiring manual bypass ("Advanced" -> "Proceed to unsafe").
    * In hackathon venue Wi-Fi networks with "Client Isolation" / "AP Isolation" enabled, peer-to-peer WebRTC
      and WebSocket connections between smartphones and the laptop server may be blocked by network switches.
  - Recommended Workaround for Live Demos:
    * Use a dedicated portable Wi-Fi router / smartphone mobile hotspot for the presentation environment.
    * Pre-install a trusted local Certificate Authority (CA) root certificate using `mkcert` on test devices,
      or deploy behind an ngrok / Cloudflare tunnel with valid trusted SSL.

PROBLEM 5: ADVANCED VISUAL VEHICLE RE-IDENTIFICATION (RE-ID) (PHASE 15 ROADMAP)
  - Issue: The trajectory tracking module links vehicle journeys across cameras primarily using recognized
    license plate strings (with fuzzy Levenshtein tolerance).
  - Impact:
    * If a vehicle's license plate is completely covered (mud, intentional masking, trailer hitch, or extreme
      glare), the system cannot associate the vehicle across cameras.
  - Planned Solution (Phase 15):
    * Integrate a visual vehicle Re-ID deep learning model (e.g., OSNet / FastReID / MobileNetV4) to extract
      a 512-dimensional appearance embedding vector (body shape, color, make, model, distinguishing marks),
      enabling plate-free trajectory stitching.

PROBLEM 6: NIGHT-TIME HIGH-BEAM HEADLIGHT GLARE & LOW-LIGHT NOISE
  - Issue: Direct vehicle headlights shining into a camera lens at night cause sensor blooming and severe
    contrast clipping, washing out the license plate mounted between the headlights.
  - Solution Needed:
    * In outdoor deployment, utilize cameras equipped with Wide Dynamic Range (WDR), IR bandpass optical
      filters, and synchronized infrared strobes.
    * Add an automatic exposure/gamma compensation filter in the enhancement pipeline for dark frames.
